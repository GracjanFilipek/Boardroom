The project manager

It thinks for itself, and it does not stop.

Most agent tools wait for your next prompt. This one has a manager whose job is to have the ideas. You set the direction once. The manager owns the roadmap from there.

What you write, once
A tool for freelancers to send invoices. Make it good.
You, Chief Executive
What the manager comes back with (example)
  1. Round 1
    Smallest version that sends one invoice

    An empty repository gets a running core first: one client, one invoice, a PDF.

  2. Round 1
    Invoice numbering that survives deletes

    Tax offices expect gapless numbers. Nobody asked for this. The manager raised it.

  3. Round 2
    Late-payment reminders

    Proposed after reading what round 1 shipped and seeing due dates had no follow-up.

  4. Round 3
    Recurring invoices for retainers

    You rejected a dashboard with the note "too early". The manager changed course.

It reads before it proposes

Every round starts in the code. The manager knows what exists, what shipped last and what is half-finished.

It decides the how, too

Each idea arrives as a work order with the architecture decisions already made: data shapes, files to touch, how to verify.

It keeps coming back

When the board runs low, it drafts the next round. Your rejections and their reasons shape what it proposes next.

How work flows

From idea to shipped, and only one step needs you.

  1. 01

    The manager proposes

    It reads the repository and your brief, then writes work orders. Anything a person will see goes to the designer, who adds the design spec.

  2. 02

    You decide

    Approve or reject from your Desk. A rejection can carry a reason, and the manager reads it before the next round.

  3. 03

    Developers build

    A free developer picks up the task, edits files in the project folder, runs the tests and commits.

  4. 04

    The manager reviews

    It checks the diff against the work order. Work that fails review goes back. A dispute that will not settle comes to you.

Human out of the loop

Switch on autopilot. Keep a hand on the brake.

On autopilot the manager's proposals go straight to the developers. Left alone, agents would run until your Claude limit. Four brakes stop them first.

Agents' share of your 5-hour window 6.0% of 10%

Claude Code reports how full your subscription window is after each run. Boardroom reads that number and holds new work once the agents have used their share.

10%
Share of the window. Agents stop after burning this slice of your 5-hour or weekly limit.
80%
Ceiling. Agents stop once the window is this full, your own usage included, so you keep room to work.
10 / day
New tasks per project. The manager stops proposing when the day's quota is used.
2 rounds
Review limit. After two failed reviews the task leaves the loop and lands on your desk.

Those are the defaults. Each one is a setting.

What else is in the box

Built for running real repositories.

Directives

Write a task yourself and it skips approval. The next free developer takes it.

Chat archive

Past Claude Code sessions on your machine show up on their own. claude.ai chats import from a data export.

Handovers

Hand an old chat to a project. Claude compresses it into a brief the team reads before each run.

Permission allowlist

Developers edit files, use git locally and run your test command. Any other shell command is denied.

Stays on your machine

The server listens on localhost only. Projects, tasks and logs live in one SQLite file in your user folder.

Desktop app

One window for macOS, Windows and Linux. The browser version runs from the same code.

Your first hires

Each project gets a manager, a designer and up to six developers.

Get it

Three commands to open the Boardroom.

In the project folder
$ npm install
$ npm run app
# or try it with canned agents, no Claude calls
$ npm run app:demo
  • Node 22.13 or newer. The server has no other dependencies.
  • Claude Code, logged in. Agents run as claude -p under your own login, on a Pro or Max plan or an API key.
  • A folder to work in. Point a project at a repository, or let Boardroom create an empty git workspace.
