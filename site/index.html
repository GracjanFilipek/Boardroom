The project manager

It thinks for itself, and it does not stop.

Most agent tools wait for your next prompt. This one has a manager whose job is to have the ideas. You set the direction once. The manager owns the roadmap from there.

What you write, once
A tool for freelancers to send invoices. Make it good.
You, Chief Executive
What the manager comes back with (example)
  1. Round 1
    Smallest version that sends one invoice

    An empty repository gets a running core first: one client, one invoice, a PDF.

  2. Round 1
    Invoice numbering that survives deletes

    Tax offices expect gapless numbers. Nobody asked for this. The manager raised it.

  3. Round 2
    Late-payment reminders

    Proposed after reading what round 1 shipped and seeing due dates had no follow-up.

  4. Round 3
    Recurring invoices for retainers

    You rejected a dashboard with the note "too early". The manager changed course.

It reads before it proposes

Every round starts in the code. The manager knows what exists, what shipped last and what is half-finished.

It decides the how, too

Each idea arrives as a work order with the architecture decisions already made: data shapes, files to touch, how to verify.

It keeps coming back

When the board runs low, it drafts the next round. Your rejections, and anything you tell it in conversation, shape what comes next.

How work flows

From idea to shipped, and only one step needs you.

  1. 01

    The manager proposes

    It reads the repository and your brief, then writes work orders with the architecture already decided.

  2. 02

    The designer specs it

    Anything a person will see gets a design spec first: layout, every state, exact wording, the tokens to use.

  3. 03

    You decide

    Approve or reject from your Desk. A rejection can carry a reason, and the manager reads it before the next round.

  4. 04

    Developers build

    Free developers pick up tasks in parallel, edit files, run the tests and commit. A blocked command pauses and asks you.

  5. 05

    The manager reviews

    It checks the diff against the work order and the design. Approved work is pushed to GitHub.

Human out of the loop

Switch on autopilot. Keep a hand on the brake.

On autopilot the manager's proposals go straight to the developers. Left alone, agents would run until your Claude limit. Four brakes stop them first.

Agents' share of your 5-hour window 6.0% of 10%

Claude Code reports how full your subscription window is after each run. Booardroom reads that number and holds new work once the agents have used their share.

10%
Share of the window. Agents stop after burning this slice of your 5-hour or weekly limit.
80%
Ceiling. Agents stop once the window is this full, your own usage included, so you keep room to work.
10 / day
New tasks per project. The manager stops proposing when the day's quota is used.
2 rounds
Review limit. After two failed reviews the task leaves the loop and lands on your desk.

Those are the defaults. Each one is a setting.

Supply-chain safety

Agents invent package names. Attackers register them.

The attack is called slopsquatting: a model suggests a package that sounds right, someone has already published malware under that name, and an unattended agent installs it. Booardroom checks every package before any agent installs it.

What a developer sees
$ npm install express react-pretty-state

slopsquat-guard blocked this install.
BLOCK  react-pretty-state: does not exist on the
       registry (likely a hallucinated name)
Do not retry with another guessed name. Find the
real package in the project docs or on npmjs.com.
Blocked
The name does not exist. The install is refused and the developer is told to find the real package.
Asks you
It exists but looks wrong. New on npm, almost no downloads, or one letter away from a popular name. The developer stops and you decide.
Always on
The model cannot skip it. The check runs in front of every shell command, for every agent, on npm, pnpm, yarn and bun.

The check is slopsquat-guard, our own open-source plugin for Claude Code. It is one layer of defence. It does not read package source code.
